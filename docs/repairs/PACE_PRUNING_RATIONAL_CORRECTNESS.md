# PACE search-time pruning audit under rational preference semantics

**Status:** audit completed; the existing PACE-X/PACE-B search predicates are not proved conservative for the rational objective. PACE-X global certification is disabled in the experiment adapter. PACE-B is reported only over its retained candidate registry. This audit is not an approval to run or freeze experiments.

## Required invariant

Any lower bound used to exclude a state must satisfy `computedLowerBound <= true minimum remaining travel time` everywhere in its claimed temporal domain. Residual budgets may not be rounded down. A score upper bound used for exclusion must satisfy `true best attainable score <= computedUpperBound`; strict score inferiority must be established on every cell and owned endpoint. A `COMPLETE` status is not sufficient if any arithmetic pruning predicate has no proof.

Current search code mostly stores time and travel quantities as doubles and uses `Domain.canonicalTime` (12-place HALF_EVEN) after arithmetic. That is a useful canonical legacy model, but the operations do not carry directed-rounding bounds. No general proof was found that intermediate sums, differences, ratios, or comparisons are biased in the safe direction for arbitrary accepted rational input and path length.

## Predicate inventory

| Component / decision | Intended invariant | Current arithmetic and result | Can it omit a feasible or optimal route? |
| --- | --- | --- | --- |
| `QueryLowerBounds`: per-edge minimum travel weight | Weight is no greater than the edge's true minimum duration over query support. | Minimum is returned as a `double`; it is used as the edge weight in forward/reverse Dijkstra. No rational or downward-directed representation is carried. | Not proved conservative. An upward represented minimum can inflate every later lower bound. |
| `QueryLowerBounds`: forward and reverse Dijkstra / radius truncation | Distances are lower bounds from source/to destination; truncation removes only labels strictly beyond the budget radius. | Canonicalized double additions, exact `double` equality/tie checks, and `candidate <= maximum` / `current > maximum`. | Not proved conservative; may remove a budget-feasible route or make corridor labels unreachable. |
| `QueryCorridor.build` arc test | For every route using `(u,v)`, `d(s,u)+minTau(u,v)+d(v,d) <= B` implies the arc is retained. | Prefix, edge and suffix lower-bound doubles are added, canonicalized, then compared with canonical budget using strict `>`. | Not proved conservative; upward rounding can remove the arc and every route that needs it. `QueryCorridor.unpruned` exists as an all-arcs ablation, but is not selected as a rational PACE fallback in this change. |
| `ForwardLayeredFrontierGenerator.residualDomain` and final/pivot admission | Candidate prefix travel plus a lower bound on the remaining suffix fits `B` on each retained departure cell. | Double `requiredLowerBound`, budget subtraction, `minimumTravelTime`, and `domainWhereTravelTimeAtMost`; several results are canonicalized to 12 places. | Not proved conservative; a false empty domain stops final connector or pivot expansion. |

| `BoundedConnectorGenerator` reverse heuristic and completion checks | Reverse labels and partial-plus-remaining costs are admissible lower bounds. | Reverse Dijkstra and DFS/A* completion totals use canonicalized doubles and strict `>` comparisons against residual budget. | Not proved conservative; can reject a feasible connector. |

| `QueryScopedConnectorLabelStore` / connector cache key | Reuse only a label portfolio generated for an equivalent domain, residual budget, and looplessness state. | Request keys include `Domain.toString`, bit masks, and `Domain.canonicalTime(residualBudget)`. | No rational-equivalence proof for computed residuals. | `SafeScoreUpperBound.cannotImprove` | Upper bound is at least the best score reachable by the candidate; equality is retained for travel/path tie rules. | Computes `maxScore/minTravel`, canonicalizes the rate, then uses double subtraction/multiplication/addition. Capped outputs must not claim global completeness. |
| PACE completion/certificate conditions | Global certification requires exhaustive route coverage and all pruning rules sound. | `PaceGenerationResult` validates completion/cap consistency, but legacy arithmetic predicates remain in the candidate engine. | A legacy `COMPLETE` label alone is insufficient. Structural directed-edge checks and visited-vertex/path-loop checks are not numerical pruning. They enforce the declared directed vertex-simple route domain. Candidate limits and work caps are explicit bounded-search policy rather than claims of safe rational pruning.

## Correctness-preserving validation path

For bounded fixtures, `TinyContinuousEnvelopeOracle` independently enumerates directed vertex-simple paths without PACE corridor, lower-bound, score-bound, or dominance pruning. It computes whole rational temporal cells and provides both `solveCellsForPaths` (a supplied emitted registry) and `solveCells` (the global simple-path optimum). This is the correctness-preserving controlled validation fallback used by the cross-method regression. It is test-only and exponential; it is not used on full networks.

The checked-in PACE-B policy remains bounded and useful for retained-frontier experiments, but there is no PACE-X global exact reference under G2/G3 until every listed predicate is either proved conservative or replaced for that configuration. No unpruned PACE search mode is represented as implemented here.
