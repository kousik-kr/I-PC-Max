# Preference algorithm numerical migration plan

This source audit records the scope of the M5-R2 exact evaluator and the changes required before PACE-X, PACE-B, iSCOPE and SICSP-Pref can be compared under one declared rational objective model. “Exact evaluator” below means final route replay and continuous preference-envelope selection; it does not imply that search, lower-bound pruning or candidate dominance used the same arithmetic.

## Source-level matrix

|---|---|---|---|---|

Known counterexample: the shared fractional-root profile/replay disagreement. | Yes, for the final envelope over its emitted route registry. This would certify only that registry. | Corridor construction and forward frontier pruning use `QueryLowerBounds`, canonical double budgets, residual budgets and legacy temporal/profile operations. ## Required migration sequence

1. Freeze the accepted graph input contract: canonicalized decimal knots/values, FIFO and support assumptions, departure/budget canonicalization, score boundary ownership, and output serialization.
2. Migrate exact path replay, score-event pullbacks, budget domains and continuous envelope selection for each adapter. Keep the old output only as an explicitly rounded compatibility projection.
3. Trace every search-time temporal decision: lower-bound truncation, residual budget, corridor checks, label/dominance pruning, score bounds, candidate grouping, and endpoint inclusion. Replace it with the same rational model or prove it is conservative for that model.
4. Compare every emitted route registry and final exact envelope with independent rational whole-cell oracles on tiny graphs. Separately test missing globally optimal routes so search incompleteness is not mislabeled as evaluator error.
5. Reassess each adapter scope. Only a complete algorithm with verified exact pruning may claim a global certificate. Bounded and heuristic variants remain registry-scoped even when their final envelopes are exact.
6. Run matched-workload comparisons only after every compared objective evaluator uses this contract. Until then, label numerical-model differences and withhold unqualified preference-quality comparisons.

No PACE-X, PACE-B or iSCOPE production behavior was changed in M5-R2. The current exact SICSP-Pref repair does not establish that all preference algorithms share a common exact model.
