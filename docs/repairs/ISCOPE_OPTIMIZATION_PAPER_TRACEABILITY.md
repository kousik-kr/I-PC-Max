## Unspecified paper details resolved in code

The paper does not provide a threshold value or a rule that uniquely partitions all neighboring breakpoint clusters. The implementation defaults to a **2-minute maximum cluster span**, configurable only for `iscope-optimized`; clustering uses a deterministic left-to-right greedy scan and only merges a group with at least one interior breakpoint. It never drops the endpoints of a support component. This is an experiment parameter, not a paper constant.

The paper describes roulette for one intermediate score at a time but does not fully prescribe how to combine multiple removed breakpoints. The implementation folds each interior score into the current representative from left to right. It uses a `SplittableRandom` seeded by a stable hash of the configured seed, query endpoints, canonical departure domain, and canonical budget. For integer draw `r` and nonnegative scores `a,b`, it chooses `a` iff `r(a+b) <= 100a`; this is the paper's inclusive comparison without binary floating point. If `a=b=0`, it chooses the current value for draws 0–50 and the incoming value for 51–100. The seed, threshold, roulette policy, draw count, merge count, piece counts, and local maximum observed arrival error are serialized.

The repository's `TDGraph` contains integer coordinate fields, but no contract establishes their physical units or a safe maximum speed applicable to all road edges. The paper's Euclidean/maxSpeed expression is therefore not assumed admissible. The exact edge-minimum fallback has a direct lower-bound proof documented separately.

## Acceptance boundary

`iscope-opt1` passed the exhaustive tiny-graph candidate-registry and whole-cell oracle tests and may claim `GLOBAL_CERTIFIED` only after uncapped DFS plus complete exact evaluation. `iscope-optimized` exercises Opt1 and Opt2 and is never certified globally. Its final exact schema asserts route continuity, exact budget feasibility, exact edge-entry scores, and exact best-route selection for the retained registry. It makes no claim about paths excluded by approximation.

Thus `iscope-optimized` is a paper-inspired, explicitly adapted baseline. The source-level result is **implementation validated for the declared adaptation**, not full paper-fidelity acceptance. The five-second setting is enforced in Java CLI validation and the prospective compact config. No full NY/FLA/CAL query jobs were run.
