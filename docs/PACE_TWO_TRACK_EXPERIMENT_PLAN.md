# PACE two-track experiment plan

This document supersedes the old USA/E00--E13 launch plan. The executable source of truth is
`experiments/configs/paper_q1_server_24c_250g.yaml`; the unprofiled copy is
`experiments/configs/paper_q1.yaml`. Both files are intentionally byte-equivalent in study
semantics and use one process at a time.

## Evaluation tracks

| Track | Dataset scope | Algorithm scope | Purpose |
|---|---|---|---|
| Exactness | NY-EXACT plus 20-pair very-low-budget probes on NY/FLA/CAL/OL | PACE-X oracle and PACE-B | certification and quality reference only |
| Scalability | NY, FLA, CAL | PACE-B and scalable baselines | feasibility, score quality, runtime, memory, robustness |
| Preparation | NY, FLA, CAL, OL | reusable dataset/query-side indexes | storage/build/checksum accounting |

OL replaces USA in the repository layout (`data/input/OL`). USA is not a configured dataset. OL is
not silently aliased to USA: missing OL payloads stop preflight.

## Studies

* **T01** (`t01_exactness_oracle.yaml`): NY-EXACT, 20 evaluation pairs, two centers, PACE-X
  and PACE-B at the very-low-budget rho 0.10 only.
* **T02** (`t02_full_network_exact_probe.yaml`): NY/FLA/CAL/OL, 20 evaluation pairs per dataset,
  two centers, rho 0.10 only, PACE-X versus PACE-B. The guard in `common/config.py`,
  `build_matrices.py`, and `execute_matrix.py` rejects PACE-X in every other study.
* **T03**: the historical ten-second source matrix
  (`t03_scalability_main.yaml`) retains PACE-B, RPQ, and IntervalBest provenance.
  The revised five-second continuation (`t03_scalability_main_5s.yaml`) uses the
  matched PACE-B, iSCOPE, and allFP matrix on NY/FLA/CAL. It is deliberately loaded
  by the T03-only `paper_q1_server_24c_250g_5s.yaml`, so the cap cannot affect T01/T02
  PACE-X. See `docs/PACE_T03_FIVE_SECOND_CONTINUATION.md`.
* **T04** (`t04_ablation_small_budget.yaml`): NY only, small-budget component ablations, score
  density 5/10/20/40% and graph seeds 42/43/44.
* **T05** (`t05_theta_sensitivity.yaml`): NY theta 1/2/3 small-budget sensitivity. The fixed
  scalable setting is theta 2.
* **T06** (`t06_precomputation.yaml`): derived preparation accounting for NY/FLA/CAL/OL.

The fixed default PACE-B configuration is theta=2, L=4, K_c=4, K_f=2,
M_c=250,000, M_b=100,000, and M_q=5,000,000. `resolved_pace_b_required=false` is deliberate:
these values are the final frozen scalable defaults, not values inferred from the exact oracle.
Query-internal threads remain an axis of the sensitivity plan, with one query process and a hard
24-thread maximum. The executor adds one JVM heap ceiling (`-Xmx250g` for the server profile), not
one heap per worker.

## Dataset preparation

`experiments/scripts/generate_dataset_assets.py` remains the only DIMACS conversion path and keeps
`declared_centisecond_normalization-v1` (`minutes = DIMACS_weight / 6000`). It validates unique
directed arc IDs, graph counts, checksums, FIFO arrival functions, positive lower-bound edge times,
10080-minute support, nested NY score-density variants, and configured seeds 42/43/44.

OL assets must be generated into `data/input/OL` using the existing generator configuration. The
checked-in `experiments/configs/datasets/ol.yaml` leaves counts unresolved until the actual OL
payload is supplied; preflight therefore reports a concrete missing-input blocker rather than
guessing counts.

Create the exact benchmark only after NY is validated:

```sh
python3 experiments/scripts/create_ny_exact.py --source data/input/NY \
  --output data/input/NY-Exact --nodes 10000
```

The script filters the canonical converted edge, travel-time, and score payloads by a deterministic
connected BFS node set, then deterministically remaps retained directed arc IDs to the loader's
required consecutive range. It inherits temporal/conversion metadata; it does not parse DIMACS or
create another graph representation.

## Query and launch commands

All query sets are generated by the existing Java `PaperQuerySetGenerator` through
`generate_query_sets.py`; pair selection is once per dataset and reused across every T01--T06
axis. Validation is mandatory before any query execution:

```sh
python3 experiments/scripts/generate_query_sets.py \
  --config experiments/configs/paper_q1_server_24c_250g.yaml --plan-only
python3 experiments/scripts/generate_query_sets.py \
  --config experiments/configs/paper_q1_server_24c_250g.yaml --validate-only
python3 experiments/scripts/preflight.py \
  --config experiments/configs/paper_q1_server_24c_250g.yaml \
  --output experiments/results/diagnostics/pace_two_track_preflight.json
python3 experiments/scripts/run_all.py \
  --config experiments/configs/paper_q1_server_24c_250g.yaml \
  --run-id pace_q1_two_track --stages plan --plan-only
```

The last command writes a deterministic T01--T06 matrix and starts no algorithm. A full run is
permitted only after the same config passes deep preflight and query validation; the existing
`background_run.py` resume/status controller remains the supported launcher.
